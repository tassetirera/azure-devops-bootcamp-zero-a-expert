# QCM + corrections détaillées pour l'AZ-104 - Sécurité d’accès et gouvernance

***

## QCM (10 questions) - Domaine : Sécurité d’accès et gouvernance

1. **Quel service aide à détecter des connexions suspectes dans Entra ID ?**  
   a) Identity Protection
   b) Azure DNS
   c) Azure Policy
   d) Application Insights

2. **Quel mécanisme empêche l’utilisation de mots de passe compromis ?**  
   a) Password Protection
   b) NSG
   c) VNet Peering
   d) Azure Cache

3. **Quel rôle est nécessaire pour créer des applications enregistrées dans Entra ?**  
   a) Application Administrator
   b) Owner
   c) Storage Account Contributor
   d) Reader

4. **Quel type d’identité ne peut pas être utilisé pour un utilisateur humain ?**  
   a) Identité B2C
   b) Identité d’agent IA
   c) Identité d’utilisateur
   d) Identité d’appareil

5. **Quel service permet de demander aux utilisateurs de réviser leurs accès ?**  
   a) Access Reviews
   b) Azure Backup
   c) Azure Monitor
   d) Azure DNS

6. **Quel concept est appliqué quand on sépare les tâches d’administration entre plusieurs personnes ?**  
   a) Separation of Duties
   b) Full Control
   c) Shared Secrets
   d) One Admin

7. **Quel identifiant authentifie un service Azure sans mot de passe ?**  
   a) Managed Identity
   b) User Principal Name
   c) Object ID
   d) Guest ID

8. **Quel service Azure permet de lier des applications aux utilisateurs internes et externes ?**  
   a) Entra ID
   b) Azure Storage
   c) Azure Firewall
   d) Azure Load Balancer

9. **Quel rôle est recommandé pour un administrateur de sécurité sans droits de création de ressources ?**  
   a) Security Reader
   b) Contributor
   c) Owner
   d) Reader

10. **Quel mode d’authentification est le plus sécurisé ?**  
   a) MFA
   b) Mot de passe seul
   c) Certificat non signé
   d) HTTP basique

***

## Corrections détaillées

1. **a) Identity Protection**  
   - Identity Protection analyse les signaux de connexion et de risque.

2. **a) Password Protection**  
   - Password Protection bloque les mots de passe compromis.

3. **a) Application Administrator**  
   - Application Administrator gère les applications enregistrées.

4. **b) Identité d’agent IA**  
   - Une identité d’agent IA est destinée aux bots/workflows, pas aux humains.

5. **a) Access Reviews**  
   - Access Reviews révisent régulièrement les droits d’accès.

6. **a) Separation of Duties**  
   - Separation of Duties réduit les risques en divisant les responsabilités.

7. **a) Managed Identity**  
   - Managed Identity permet l’authentification sans secret.

8. **a) Entra ID**  
   - Entra ID est le service central pour identités internes et externes.

9. **a) Security Reader**  
   - Security Reader peut consulter la sécurité sans modifier les ressources.

10. **a) MFA**  
   - MFA reste le mode d’authentification le plus fort.
